# occam-resume

> 如无必要，勿增实体。

一套用 AI 写简历的个人方法论工具包：把「原始工作记录 + 目标岗位 JD」转成职业化、极简、能让面试官
快速形成关键词印象的简历内容。

奥卡姆剃刀是这套方法论的内核——砍掉没有场景支撑的「专业技能」章节，砍掉分散视觉中心的加粗，
砍掉与主线无关的经历，只留下能被证据坐实的关键词。

仓库包含一个可直接安装到 Claude Code 的 skill，以及一组配套的输入 / 输出示范。

## 目录结构

```
occam-resume/
└── skills/
    └── resume-content-style/
        ├── SKILL.md                                # 简历内容与风格标准（核心）
        └── examples/
            ├── input-jd-marketing-backend.md       # 样例输入：营销中台 Java 服务端 JD
            └── output-resume-marketing-backend.md  # 样例输出：按 SKILL.md 产出的简历
```

- [SKILL.md](skills/resume-content-style/SKILL.md) —— 简历内容的硬约束、验收标准、反模式与踩坑记录。
- [样例 JD](skills/resume-content-style/examples/input-jd-marketing-backend.md) —— 电商营销中台 / 优惠系统方向的 Java 服务端岗位。
- [样例简历](skills/resume-content-style/examples/output-resume-marketing-backend.md) —— 对应这份 JD 产出的完整示范，含关键词闭环自检表。**姓名、学校、公司、项目和全部数字均为虚构**，仅用于演示结构与写法。

## 方法论一句话版

好简历的终点是：面试官扫读十几秒后，记住 **3–5 个与 JD 高度吻合的关键词**。

围绕这个终点，简历自上而下固定为五段：

1. **个人基本信息** —— 放头部，姓名、电话、邮箱、求职意向。
2. **个人总结** —— 抢注意力的地方。4 条能力 + 1 条技术栈，每条开头一个加粗锚点词，锚点由 JD 维度反推得到。技术栈那一行同时承担 ATS 关键词覆盖，因此**不再单设「专业技能」章节**。
3. **教育经历** —— 一行写完，学校、专业、学历、时间。
4. **工作经历** —— 职业画像：负责过哪些项目（点名即可）、团队与跨团队协作、技术影响（奖项写在这里）。具体工程建设下沉到项目经历。
5. **项目经历** —— 篇幅占比最高，**1 个主项目 + 1~2 个辅助项目**。主项目坐实个人总结的锚点；辅助项目补维度，典型组合是「生产事故排障与后续优化」+「AI 相关经历」。

两条贯穿全文的规则：

- **关键词闭环**：JD 要求 → 个人总结锚点 → 项目证据，三者必须对得上。总结里说的能力，正文里要看得到证据；JD 的核心要求，简历里要找得到落点。
- **克制加粗**：正文只有 bullet 开头的锚点短语加粗，数字、技术名词、整句正文一律常规字重。加粗越多，视觉中心越散，关键词反而抓不住。

每条成果 bullet 用 XYZ 组织：X（做成了什么）+ Z（采取了什么行动）为必备，Y（衡量指标）有可辩护的真实数字时才加。

## 安装到 Claude Code

把 skill 目录软链或复制到 `~/.claude/skills/`：

```bash
ln -s "$(pwd)/skills/resume-content-style" ~/.claude/skills/resume-content-style
```

之后在会话中说「按这份 JD 帮我写简历」「改简历」等触发词即可命中，或直接 `/resume-content-style`。

## 配套 skill

- `jd-search` —— 采集目标岗位 JD，作为本 skill 的输入。
- `resume-ng-latex` —— 把定稿内容排成 1–1.5 页的中文 PDF 简历。排版环节不改写措辞。

## 使用边界

- 原始工作记录是唯一事实来源，skill 不编造经历、学历、职级、奖项和数字。
- 凡是推算出来的数字，交付时必须逐条说明依据，由本人决定是否采用。
